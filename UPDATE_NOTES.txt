FRONTLINE UPDATED PROTOTYPE - UI / CAMERA / MAP PASS

Changes in this update:
- Increased the procedural world footprint from 200x200 to 260x260.
- Added additional building sites, trees, rocks and distant hills using lightweight procedural meshes.
- Reworked MobileUI positions into a larger two-column touch layout.
- Enlarged FIRE and AIM controls and added readable font sizes and rounded dark button styling.
- Repositioned the health/ammo/weapon HUD to avoid overlap.
- Made the on-screen joystick larger and responsive to viewport height.
- Raised the camera pivot slightly and increased the third-person spring-arm distance.

Important:
- This remains a prototype and uses procedural placeholder geometry for most map assets.
- The project has not been run inside the Godot editor in this environment, so please test it in Godot 4.7.2.
- Original user ZIP should be kept as a backup. This is a separate updated copy.


UPDATE v3 - WEAPON ROSTER + MINIMAP
- Added a live top-right minimap with player marker, red enemy markers, and yellow loot markers.
- Added M416, AKM, SCAR-L, Groza, AWM and Pistol weapon profiles with separate damage, fire delay, reload time, magazine size and reserve ammo.
- HUD weapon label now shows the selected weapon and standard magazine capacity.
- AWM is configured with a 5-round magazine for this prototype.
- Note: this is still a prototype; weapon models/animations and final Android runtime testing remain to be done.


UPDATE v4 - WEAPON LOOTING
- Added procedural 3D pickup silhouettes for AKM, SCAR-L, Groza and AWM near map buildings.
- Added a mobile-button compatible pickup action through the existing PICKUP button.
- M416 and Pistol are available at the start; other rifles unlock when picked up.
- Weapon switching now cycles only through unlocked weapons. Picking up a new weapon loads one magazine and gives two magazines in reserve; duplicate pickups add one magazine of reserve ammo.
- These are lightweight placeholder meshes, not final imported PUBG-quality weapon assets.
- Runtime validation in Godot was not available during this edit; test the project in Godot 4.7.2 before replacing your working copy.


UPDATE v5 - HELD WEAPON VISUALS + SHOOTING FEEDBACK
- Added a lightweight procedural weapon model to the third-person soldier. It updates when the player switches or picks up M416, AKM, SCAR-L, Groza, AWM or Pistol.
- Added a short muzzle flash when firing.
- Added a brief bullet tracer from the camera toward the raycast hit point.
- Added a red hit marker when a shot damages a target.
- These are prototype meshes and simple visual feedback, not final rigged hand-bone attachments, realistic weapon assets, or full reload/fire animations.
- Godot runtime testing was not available in this environment; please test the separate copy in Godot 4.7.2. Keep your previous ZIP as a backup.


UPDATE V6 — LIMITED SURVIVAL INVENTORY
- Added on-screen inventory counts for grenades, smoke grenades, energy drinks, first aid kits, and medkits.
- Consumable use now reduces item counts and blocks use when stock is empty.
- Loot crates replenish limited consumables, health, and energy.
- This remains a prototype; Godot runtime validation is still required.

UPDATE v9 — AIM FEEDBACK + SHOULDER AIM
- Aim button now informs the player controller, moves the camera closer, and narrows the field of view for a more focused third-person aim mode.
- While aiming, the soldier turns toward the camera's facing direction and movement speed is reduced; sprint is disabled while aiming.
- Center crosshair turns red and changes symbol when its center ray is pointing at an enemy, providing visual feedback before firing.
- Firing still uses the camera-center ray, so the crosshair and shot direction use the same aiming line.
- Static resource/path checks only; Godot runtime is not installed in this environment, so import/play testing is still required.

v10 additions:
- FIRE button now supports hold-to-fire on touch screens and mouse clicks.
- Weapon fire rate remains governed by the player's existing cooldown, so holding the button does not bypass weapon timing.
- Release FIRE to stop shooting. Runtime testing in Godot is still required.

UPDATE v11 — PAUSE / RESUME FLOW
- Added a touch-friendly pause button below the minimap.
- Added a dark pause overlay with RESUME and RESTART MATCH buttons.
- Escape toggles pause on PC; game simulation pauses while the overlay remains interactive.
- Pause UI is generated by scenes/pause_menu.gd and uses Godot built-in controls only.
- Static resource checks and ZIP integrity checks only; please run in Godot 4.7.x to verify runtime behaviour.
